Strategic Memory Collector Agents and a Serverless Markdown Sharing Network

A shared place for project documents, plus a local agent that turns completed engineering work into lessons worth reviewing.

1. Why I built this

  • Useful documents often stay inside individual agent runs, chats or project folders.
  • The sharing network gives selected Markdown a common home, so people can find and reopen it.
  • The strategic memory collector adds a second step: identify durable lessons from completed work and prepare them for review.
  • Documents preserve the working detail. Memory candidates capture a smaller decision, procedure, convention, failure shield or user preference that may help later work.

The current design combines an Angular Telemetry UI and a Flask/FastMCP runtime on AWS Lambda. The collector runs independently on the local machine, using LangGraph and a Bedrock Qwen adapter.

2. AWS architecture: from the watcher to stored Markdown

  • Watcher: detects changed Markdown within the configured project and sends an authenticated, device-signed snapshot.
  • Amazon Cognito: supplies the user identity and tokens; API Gateway verifies the native upload JWT.
  • API Gateway and Lambda: route the request to the single Telemetry runtime, where document code validates identity, device proof, paths and content.
  • Amazon S3: stores the Markdown bytes. DynamoDB: stores the document index and related project, task and device records.
  • READY receipt: confirms the acknowledged document write; an unknown result needs reconciliation before a retry.

One Lambda runtime for UI, native uploads and MCP

  • telemetry-api/server.py dispatches browser API and authenticated FastMCP routes in one application image.
  • The Lambda Web Adapter runs the web application inside Lambda. Its execution role grants the scoped storage permissions.
  • Native uploads, browser sessions and MCP OAuth retain separate authentication boundaries and share the document storage implementation.
  • The current application replaces the earlier ECS-hosted document-service approach. The collector remains a separate local process.

Where MCP fits

  • An assistant explicitly calls save_markdown with document content and context; the watcher handles local Markdown changes separately.
  • The MCP edge forwards protocol and OAuth requests to the same API Gateway and Lambda runtime.
  • LangChain’s MCP adapter belongs on the agent/client side. FastMCP exposes the saving tool on the server.
  • The saving tool stores documents. Agent-side document search and memory-candidate publication require separate integration.

3. The watcher keeps shared documents current

  • Recursively checks .md files under its configured project root, excluding watcher runtime directories.
  • Waits for stable bytes and compares content hashes so unchanged files do not trigger another upload.
  • Uses project-relative paths to preserve identity as a document changes.
  • Marks an upload complete only when its file identity and hash match the returned READY receipt.

For example, editing docs/design.md produces a new snapshot for that document’s shared identity. Editing application code alone does not upload a document.

4. How the strategic memory collector works

The collector asks a narrow question: what did this completed task teach us that will still be useful later? It receives a bounded completion manifest rather than reading the full conversation or scanning the repository.

  1. Receive completed-task evidence. The parent workflow supplies the project and task IDs, source revision, completion time, final summary, changed paths and check results. Admission requires a complete status and at least one passed check. The parent remains responsible for truthful completion evidence.
  2. Commit the job before model work. enqueue validates the manifest, saves an idempotent job in SQLite and starts a detached drainer. It returns a job ID without waiting for inference.
  3. Extract candidate lessons. LangGraph runs extract → gate → persist. The Bedrock Qwen adapter receives the supplied summary, path references and passed-check references, and returns schema-constrained candidates. A task with no durable lesson can produce an empty list.
  4. Validate the proposals. Pydantic checks the candidate shape and bounded fields. Heuristic rules reject sensitive or explicitly transient text; the evidence gate requires references from the supplied manifest and removes duplicate text. Reference checks do not prove a lesson is logically correct.
  5. Persist for review. Accepted candidates and the successful job receipt commit together. Each candidate records its category, content, scope, evidence references, confidence and when it should be revalidated.
  6. Let a person decide what to retain. The local CLI exposes status and candidates. A separate human-authorized workflow decides whether a lesson belongs in an authoritative project document, instruction or memory source.

What it collects

  • Architecture decisions: a stable choice and the scope in which it applies.
  • Failure shields: a reusable way to prevent a demonstrated mistake.
  • Procedures and conventions: repeatable steps and project rules supported by the task evidence.
  • User preferences: durable guidance supported by the supplied completion summary.

Recovery and review

  • status shows queue progress; candidates --project PROJECT_ID exposes the review view.
  • drain can reclaim interrupted work after its lease expires; provider failures require an explicit retry JOB_ID.
  • SQLite holds queue state and candidate records; LangGraph checkpoints preserve intermediate history.
  • Deduplication compares normalized text. It does not perform semantic similarity search.

Current integration boundary: the collector package is implemented, but parent completion hooks are not installed. Installing it does not intercept every agent run. It never edits source, native Codex memory, skills, prompts or AGENTS.md, and it does not promote candidates automatically.

5. Access shared documents through Telemetry

  • Sign in and open Workspace → Documents.
  • Filter by category or My documents, search the loaded list, and load more pages as needed.
  • Select a document to read or edit its Markdown.
  • Save an eligible owned document with a version check; otherwise save an edited copy in your own folder.
  • Upload Markdown directly when a document does not arrive through the watcher or MCP.

The UI and document clients use the same storage code. Memory candidates remain in the collector’s local review store; they are not currently listed in Telemetry Documents.

6. What is implemented and what remains separate

  • Application source: Angular UI, one Flask/FastMCP Lambda runtime, and shared S3/DynamoDB document services.
  • Infrastructure: CDK and template examples describe identity, API, Lambda, edge and data resources using fictitious configuration.
  • Collector: manifest validation, durable queue, detached worker, Bedrock adapter, evidence gates and local candidate review.
  • Still separate: parent completion-hook installation, authorized memory promotion and any future Telemetry candidate view.
  • Release boundary: repository CI validates code; it does not deploy AWS resources. Current source and fake-model tests do not establish a live deployment, private login or successful Bedrock inference.
