This describes the current local instructions, configuration and source. Examples show how to reproduce checks; they are not proof of a fresh install, backend memory health or cloud readiness.

Guidance and execution have different jobs

A tool performs an operation. A skill explains when and how to combine operations. A workflow defines the project’s stages and evidence expectations. The agent interprets results and decides what to do next within the user’s scope. None of these files can guarantee that an application is correct without observing it.

A concrete change: new portfolio content

For this portfolio, a new article starts as a standalone HTML document in public/read. Its metadata belongs to src/app/content/content.catalog.ts. Angular fetches that document through ContentService, and a sandboxed iframe renders its markup and relative stylesheet. Authored HTML stays outside the application template.

Resource Responsibility Evidence
content.catalog.ts ID, title, summary, HTML location and optional topic Correct route and selected sidebar title
ContentService Validate metadata/URL, fetch and isolate HTML Loading/error/retry and sandbox checks
public/read/reading.css Compact typography and HTML diagrams Desktop/mobile inspection and no content clipping

A typo in a title can be handled directly. A change to loading, sandbox policy or route behavior has a wider contract and needs a proportionate reviewed plan. The impact and uncertainty determine the route, rather than the number of files.

Plan, implement and verify in the main thread

For planned changes, workflows/development.md points to plan-development and implement-development. Planning inspects source and defines observable criteria. Implementation follows those criteria, checks the final changes and records what actually passed. A changed architecture or scope returns to planning; a routine local defect can be fixed within the existing plan.

Give repeatable work a narrow entry point

A skill’s description lets the agent decide whether it is relevant; SKILL.md provides the procedure, with supporting scripts/templates only where needed. Repository discovery exposes selected workspace skills through .agents/skills links; the maintained instructions live under the configured skill directory.

  • python-development: validation boundaries, readable structure, architecture and code-map conventions for real Python changes.
  • ui-testing-and-debugging: clear requirements, Computer Use observations, DevTools diagnosis and fix/retest evidence.
  • glue-pipeline-builder: dedicated MatchLake contracts and delivery/recovery gates; not a generic requirement for all AWS work.
  • plan-development / implement-development: the project’s planned engineering stages.
  • project-expertise workflow: discovery and solution design when a brief needs refinement before building.

A skill is editable project guidance, so keep it specific and consistent with the user’s current instructions. Update the narrow responsible procedure when a repeatable failure is found, rather than duplicating a rule across every document.

Use results to decide what comes next

A successful command exit may still leave the wrong page, a stale artifact or a missing integration. Inspect the result against the requirement: the article loaded, the diagram fits, the route selects the correct entry, and relevant requests and console output are explained.

  • Preserve another worker’s edits and give parallel work exclusive ownership.
  • Keep task records under the affected project; shared UI records use the canonical UI tool directory.
  • Separate local tests, browser observations and cloud/deployed checks.
  • Report a concrete blocker when required evidence cannot be obtained. Do not convert an unrun check into a pass.
