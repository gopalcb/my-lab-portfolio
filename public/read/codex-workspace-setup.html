SYSTEM DESIGN / SETTING UP THE CODEX WORKSPACE

Build a repeatable GB Systems workspace by separating native Codex capabilities from the local conventions, tools and evidence that shape how work gets done.

WORKSPACE SNAPSHOT · 18 OCTOBER 2026

This describes the current local instructions, configuration and source. Examples show how to reproduce checks; they are not proof of a fresh install, backend memory health or cloud readiness.

Start with the layers

Codex supplies the conversation, model access, tool calls and session execution. The GB Systems .codex folder adds working instructions, role definitions, reusable skills, workflows and small local tools. A folder full of Markdown does not itself create a scheduler or grant an agent more permissions.

Put each resource in a clear place

Workspace resource Purpose What to keep out
AGENTS.md Project behavior, ownership, scope and verification rules Secrets and large copied manuals
config.toml + agents/ Local defaults and bounded specialist definitions Assumptions about another account’s model access
skills/ + workflows/ Reusable task guidance and stage procedures A forced ceremony for every tiny edit
tools/ Executable helpers with their own contracts Undocumented background side effects
memories/, task records and logs Recall, durable handoffs and observations with distinct roles Copied credentials, private transcripts or fabricated proof

Resolve supporting paths from CODEX_HOME. Project paths still resolve from the affected project. A manifest such as my-work-portfolio/.codex/project.toml points to real source directories, test commands and preview settings; it is a navigation aid, not an application runtime.

Bootstrap the local helpers deliberately

From the GB Systems workspace root, select this checkout’s Codex home. Authenticate using the supported client flow; do not copy auth.json, session databases or another machine’s credentials into a repository. Review configuration and executable tools before enabling them.

# Run from the GB Systems workspace root.
export CODEX_HOME="$PWD/.codex"
codex --version
# Prepare the local helper environment when installing/rebuilding it:
python3 -m venv "$CODEX_HOME/.venv"
"$CODEX_HOME/.venv/bin/python" -m pip install -r "$CODEX_HOME/requirements.txt"
# Explicit initializer entry point after reviewing its behavior:
python3 "$CODEX_HOME/tools/initializer/on_codex_run.py"

The initializer creates runtime log files, checks for the watcher process, prepares a virtual environment when absent, then launches the configured watcher. An existing environment causes its dependency-install step to be skipped. Run a deliberate dependency check/sync when rebuilding; “the directory exists” is not a dependency-health test.

Treat routing as an explicit local choice

The inspected config.toml currently selects gpt-5.6-sol with medium reasoning. The named specialists remain low_effort (Luna/low), medium_effort (GPT-6.1 Sol/medium) and high_effort (Astra/high). These are the local snapshot, not a claim that every installation has those models.

Current project instructions keep routine work and planned stages in the main conversation. A specialist receives a bounded assignment when requested or justified. Delegating a task does not switch the parent model or authorize a persistent configuration edit.

Verify permissions and integrations in a fresh session

The current local file sets approval_policy = "never" and sandbox_mode = "danger-full-access". Describe those settings accurately and choose execution permissions consciously for a new installation. AGENTS.md expresses working rules; the actual client and environment enforce filesystem, tool and account access.

  • Confirm the loaded instructions and effective model/permission settings after reopening the client.
  • Check configured MCP tool discovery, then verify the real app or browser connection. Discovery alone does not prove GUI access.
  • Use a harmless read-only task before relying on a custom helper. Keep cloud checks separate from local checks.
  • Review plugin handlers and trust where required. Ordinary prompts must not activate the multi-agent messaging workflow.
