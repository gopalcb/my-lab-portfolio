Make one claim testable

Start with one failed synthetic-cedar registration and its source revision. Keep that request as the reproduction throughout diagnosis.

This is a runbook for a future isolated dev lab. Its commands have not been executed against EventHub; resource names are planned conventions. Start from the affected user journey, tenant, time window and first bad release. Preserve a successful comparison path. Change one bounded variable only after evidence supports the hypothesis, then repeat the original failure and the relevant correctness/security tests.

A registration timeout could be gateway routing, an exhausted DB pool, an event-loop stall or a network path. “Kubernetes is broken” is not a discriminating hypothesis. Prefer “only pods in AZ B time out reaching PostgreSQL, while same-version AZ A pods succeed.” That claim predicts which routes, security rules and connection metrics should differ.

Events expire. Logs can carry credentials or personal data: select a bounded time window and sanitize evidence. A Deployment log request is not guaranteed to aggregate every replica. Select the exact pod/container; for a restarted container, use previous logs. Metrics-server is required for kubectl top, which is neither a history store nor a profiler.

Find the first failed boundary

Trace the chosen EventHub API host through NLB, NGINX and registration before blaming its database or asynchronous workers.

NXDOMAIN is not a TCP timeout; a successful TCP handshake is not certificate validation; a trusted TLS session is not an authorized user request. A gateway 404 suggests a different route/host problem from a 504 upstream deadline, although exact status mapping is implementation dependent. Identify the first boundary whose expected observation is missing.

kubectl -n gateway-system get gateway eventhub-public -o yaml
kubectl -n apps-dev get httproute eventhub-registration -o yaml

example.test is reserved example syntax, not a selected public certificate domain. Substitute the actual domain and trusted CA path as needed. Expected TLS evidence is a valid chain and hostname; disabling verification does not satisfy the check. Avoid verbose authenticated requests that print tokens into transcripts. An approved ephemeral debug workload is preferable to adding a shell and packet tools to every app image.

PostgreSQL’s activity and lock views help distinguish a blocked query from an unavailable database; inspect metadata without exporting customer query text. Queue completion latency must be measured separately from HTTP acceptance. A 200 response before a subscriber finishes does not prove end-to-end completion.

The outbox publisher can duplicate after a crash, and an SQS worker can repeat a side effect before acknowledgement. Record event versions and durable processing keys, and reconcile external effects rather than promising exactly-once delivery. Separate notification and audit queues let both receive events while replicas within each subscription compete.

Linux observations explain Kubernetes symptoms

Start from the worker and cgroup of the selected registration replica, not an unrelated host or process.

# On exactly that worker, after approved access, with prepared tools:
date -u
df -h
df -i
free -m
vmstat 1 5
ip -s link
ip route
cat /proc/pressure/memory
journalctl -u kubelet --since "15 minutes ago" --no-pager -n 100
# Correlate with registration's termination reason and container cgroup.

For memory, compare RSS/heap trend and the actual container cgroup’s memory events with node availability and eviction conditions. For storage, compare bytes, inodes, mount mode and latency. For startup permission errors, inspect UID/GID, parent traversal permission and executable/mount flags before changing ownership. For connection errors, inspect listening address, established/retransmit/TIME_WAIT trends and FD/PID budgets. Check UTC and clock synchronization before calling a certificate expired or reordering a distributed timeline.

Bound privileged diagnostics such as namespace entry, tracing or capture to approved nodes and synthetic traffic. EKS control-plane hosts are managed: use API/audit/control-plane logs rather than claiming SSH access to etcd. Linux VM or disposable kubeadm evidence must stay labeled separately from EKS.

The source guide defines F-01–F-40 as planned coverage. This article maps all categories without claiming execution. Each future report needs a known-good digest, actual versions/profile/AZs, baseline, scoped injection/abort/restoration plan, UTC detection/diagnosis/recovery times, sanitized discriminating evidence and at least one rejected alternative cause.

  • Record the bounded fix, rerun the original reproduction, and check forbidden paths and business correctness.
  • Restore the baseline; record prevention ownership, residual uncertainty and actual cost.
  • Stop if the approved dev scope changes, shared resources appear, data-loss risk is unknown or cost/impact exceeds bounds. Destructive injections need their own concrete approved scope.

Graduation calls for at least 30 distinct drills and 12 full incident reports with composite incidents, plus timed recovery and an upgrade rehearsal. These articles run no injections, diagnostics, AWS calls or EKS tests. Their verified artifact is educational content, not a platform health report.
